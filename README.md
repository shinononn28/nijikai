# 二次会卓

TRPGの二次会で遊べる、チャット付きのブラウザパーティゲーム集です。
部屋を作って招待リンクを送れば、スマホでもPCでもすぐ遊べます。

## いま遊べるもの

- **被り列挙クイズ**(3〜12人):お題に合う言葉を制限時間内に好きなだけ書き、誰とも被らなければ+1、被ったら−1。表記ゆれ(カタカナ/ひらがな/全角半角など)は自動でまとめ、「同じでしょ」「お題外でしょ」は判定タイムに多数決で決めます。ホストはお題の引き直しに加えて、お題を自分で書くこともできます。
- **基準当て**(3〜8人):親は「重い」「魔王が欲しがりそう」などの基準を秘密で選び、子は場の言葉を2つ指名して「どっちが上?」と比べてもらいながら基準を推理する。最後に基準に一番合う手札を出して親が順位付け(1位+3・2位+2・3位+1)、基準の予想が当たりなら+2・近いなら+1、親には当てた人数分の得点。
  - 手札はゲームの中で各自が作る。用意された候補8枚から選んでも、自分で書いてもよく(候補は3回まで引き直せる)、決めきれなかった分は候補から自動で補う。親も3つの候補から選ぶか、基準を自分で書ける。基準と名詞のリストは `games/words.js`(行を足すだけで増やせる)。
- **作戦トリック**(3〜5人・協力):4色×1〜9と切り札(🚀1〜4)の40枚で、場に1枚ずつ出して一番強い札の人が取るトランプを協力でやる。任務「〇〇が赤7を取る」を全員で達成すれば成功、違う人が取ったら失敗(その場で「やらかし!」と取った人の名前を表示)。
  - ミスが「分かったはずの1枚」になるよう情報を多めに出す:手札の一部は最初から公開、色ごとの枚数は公開、各自に合図(非公開の札を見せて「この色の最高/最低/1枚だけ」)、出た札の記録、チャットの数字は自動で伏せ字。
  - ステージが進むほど任務が増え(順番指定・最後指定も)、公開される手札と合図が減る。失敗時は、別の札を出せば取らずに済んだかどうかも表示。
- **意地悪コース**(2〜6人):アルティメットチキンホースをターン制にしたもの。毎ラウンド各自にこっそり配られる3つの部品から1つを選んでコースに置き、全員が経路を計画して一斉にスタート。
  - 部品:壁・落とし穴(脱落)・トゲ(残り歩数−3)・バネ(2マス飛ぶ)・点滅床(偶数歩目は穴)・氷(途切れるまで滑る)・ベルトコンベア(矢印へ1マス、向きは置くときに選ぶ)・一方通行(矢印の向きにしか入れない)・落とし戸(スタートへ戻る)・見せかけ(ただの床)・消しゴム(前のラウンドまでに表向きで置かれた部品を消す、2人のときは出ない)。
  - ゴールで+3(1人だけなら+2)、ただし全員ゴールしたら誰も得点なし。自分の置いた罠でほかの人が止まれば+1。部品は伏せて置くと、置いた本人以外には「❓」に見える。
  - キャラクターは8種類(ジャンパー・ナナメ・タフ・健脚・ゴースト・フェザー・スケーター・いかり)からランダムに1人1種類。6人でも全員の動き方が違うので、自分だけ通れる道を仕込める。
  - 経路の計算は `public/games/course-sim.js` にまとめてあり、サーバーの本番と画面の予想で同じものを使う。
- **お絵描き当て**(2〜12人・10分前後):出題者が3つの候補からお題を選んで描き、ほかの人はチャット(または画面の回答欄)に答えを書く。正解は自動判定して、答えの言葉はチャットで「🎉 正解!」に置き換える。言い回し違いの答えは、出題者が回答の一覧から手で「正解にする」ことができる。おしい答えは本人にだけ知らせる。時間が経つと文字数と頭の文字がヒントで出る。お題は `games/words.js` の名詞リスト。最後に全員の作品をギャラリーで表示。
- **伝言お絵描き**(3〜12人・10分前後):全員が同時に回るガーティックフォン方式。全員がお題の文を書き(候補から選んでも可)、ロビーの並び順で次の人へ回し(画面に「〇〇さんから受け取り、〇〇さんへ渡します」と表示)、回ってきた文を絵に、次の人はその絵を文に…と人数分くり返す。最後にホストが1本ずつ、元のお題からどう変わっていったかをめくっていき、気に入った文や絵には「いいね」。時間切れのときは描けていた分が自動で提出される。
- **文字しばり伝言**(3〜12人・10分前後):全員同時に回る伝言ゲーム。お題(ランダムか自分で作成)を受け取った人が別の言葉で言い換えて次へ渡す。ただし、その伝言の中で一度でも使われた文字(お題の文字も)はもう使えず、自分の伝言の中でも同じ文字は1回まで。お題→伝言1→伝言2→…と人数分まわったら終わりで、自分で作ったお題は自分には回ってこない。最後にホストが1本ずつ公開し、気に入った伝言には「いいね」。
  - 伝言に使えるのはひらがな・カタカナだけ(漢字・英字・数字は不可)。お題は「表記+よみ」で、使えなくなるのはよみの文字(ランダムのお題は `games/shibari-topics.js`、自分で作るときはよみも入力)。
  - 伝言ごとに「ダミー」の使えない文字が最初から混ざっていて(設定で0〜10字)、本物と見分けがつかない。「使えない文字 − 回ってきた伝言の文字」で前の伝言を割り出せないようにするため。ダミーは結果発表で明かす。
  - 使えない文字は五十音表で×が付き、入力中の文の使えない文字はその場で赤くなる(使えない文字が入っていると提出できない。時間切れのときは使えない文字を消して自動提出)。
  - 1つの伝言の中でも同じ文字は1回まで(「ぺたぺた」は×)。ひらがなとカタカナは同じ文字として数える(設定で別にもできる)。濁点・半濁点・小さい字は既定で別の文字、設定で「元の字と同じ」(「か」を使ったら「が」も×)にもできる。全角/半角・大文字/小文字は同じ文字。記号・空白・のばし棒「ー」はいつでも使える。判定は `public/games/shibari-rules.js`(画面と共通)。
  - 設定で「最後の人は元のお題を当てる」にすると、当たった伝言に関わった全員に+1点(言い回し違いはホストかお題を出した人が「正解にする」)。
- **多数欠**(3〜12人、CPUで人数調整可・5分前後):10点がA・B(5人以上ならA・B・C)にランダムに分けられ、全員が投票。票が一番少ない選択肢に入れた人(少数派)だけがその点数をもらえ、少数派が1人だけなら2倍。同数・全員同じなら誰も得点なし。設定で「事前宣言」(守らなくていい宣言を先に公開)を入れられる。
- **価値観スライダー**(3〜10人・10分前後):答える人が「計画派⇔行き当たりばったり」のような物差しに自分の位置を0〜100でこっそり置き、ほかの人は予想して置く。差5以内で5点・10以内で3点・20以内で2点・30以内で1点、ぴったり(差0)ならボーナス+3点(0や100もこれに入るので、端だと思ったら端に置くのが一番得)。答える人には得点なし。物差しは45個の候補(TRPGネタ含む)から選ぶか、答える人が両端を自分で書ける。
- **名付けカード**(2〜10人・10〜15分):順番に山札から1枚ずつ場に出す。全員に常に同じ入力欄があり、名前を書いて送信した瞬間の早い順で決まる。正解した人は場のカードを全部もらって得点に。山札がなくなったら終わり。
  - 初めて出た絵かどうかは画面に出ない(自分の記憶で判断する)。初めての絵なら、出した人の答えがそのまま名前になる。出した人以外が答えたり、出した人がすでにある名前を答えたりするとお手つき(既定で−1点)。前に出た絵なら、名前と一致すれば正解(出した人も答えられる)。外した人はそのカードでは答えられない。
  - 減点は「お手つきだけ−1点(既定)」「不正解も−1点」「なし」から選べる。名前を見せる「覚える時間」は2〜12秒。これまでの名前をボタンでも出す、やさしめの設定もある。
  - 得点のスケーリング(序盤に積もった山だけで決まらないように):既定では山札が半分を切ってから出たカードは2点、残り1/4を切ってからは4点。設定で「正解したときの倍率(×1・×2・×4)」や「1枚1点」にもできる。
  - 絵は一般名詞の絵(りんご・ねこなど82種類)と、なんだかわからない生き物(40種類・2体ずつそっくりさん)。山札の合計枚数と使う絵柄の種類は人数で変わり(種類は少しランダム。2人で9〜11種類・4人で12〜15種類・6人で16〜19種類くらい)、ロビーで変更可。各絵柄は2枚以上。
  - 判定は名前の完全一致(ひらがな/カタカナ・全角/半角・記号の違いは無視)。設定で「一致しなければ人が判定」にすると、回答者以外の多数決(またはホスト)で正解にできる。
- **月面基地の酸素**(4〜8人、CPUで人数調整可):毎日、共有タンクの酸素の使用量(1〜4)と、みんなに見せる宣言値を同時に決めます。使った分−1が得点。宣言は一斉公開され、「合計 − 宣言合計 − 監視件数」でその日の嘘の量だけがわかります。酸素を1余分に使えば1人の本当の使用量を監視でき、会議では過半数の投票で1人を隔離(翌日は使用量1で固定)できます。6日間もてば得点最多の人、途中で尽きたら総使用量が最少の人(脱出ポッド)の勝ち。
  - イベントは固定の山札(平穏2・隕石2・補給船・太陽嵐・夜間作業・節電命令・全数調査・通信障害)から毎日1枚、翌日の予報つき。
  - タンクの初期量は「人数×日数」、生産は毎日「人数〜人数×2」。全員の平均使用量が2なら7割ほど生き残る調整です。
  - 退室した人の席はCPUが引き継ぎます。
- **怪盗と探偵**(1〜6人、足りない探偵はCPU):毎回自動生成される街で、怪盗と探偵が同時に移動先を決める追跡ゲーム。怪盗は12ターン以内にお宝を3つ盗めば勝ち、探偵は同じマスに入るか同じ道ですれ違えば確保。
  - 怪盗の移動手段は毎ターン、位置はお宝を盗んだときと、ロビーで選んだターン(既定は4・8ターン目、3・6・9や「盗んだときだけ」も選べる)に公開。怪盗の切り札は1回ずつで(残りは怪盗本人にしか見えない)、潜伏(動かずにとどまり、足取りには動いたように移動手段が載る)・高飛び(2回続けて移動)・変装(そのターンは探偵と同じマスに入ってもすれ違っても確保されない。すり抜けたことは全員に知らされる)。探偵はバス4回・地下鉄2回まで。
  - 探偵だけの「作戦」チャットがあり、発言は設定した確率で伏せ字まじりに怪盗へ漏れる(盗聴)。作戦チャットには本物の目撃通報が届き、怪盗は同じ見た目の偽の通報を3回まで送れる。
  - 怪盗をCPUにすれば、全員で協力して追いかける遊び方もできる。
- **二枚舌**(1〜6人、卓は4〜6人でCPUが埋める):赤と青の陣営に分かれ、誰が味方かわからないままダイスの嘘を読み合う陣営戦ライアーズダイス。元の「二枚舌の酒場」のエンジンと画面をそのまま移植しています。
  - 卓での発言は二次会卓のチャット欄で行います。全体チャットの発言はそのまま卓の発言になり、CPUが反応したり推理の材料にしたりします。CPUの発言もチャット欄に流れます。
  - ゲーム内の「記録」ボタンで、ログ・手帳(自分だけの情報)・カードの使用状況を見られます。
- **小国の外交**(1〜6人、国は3〜6か国でCPUが埋める):自動生成の大陸で、全員が同時に命令を出して陣取り。
  - 命令は「隣の領地へ兵を動かす(攻撃・移動)」と「他の国の攻撃や守備への援軍」。戦闘は兵の合計+サイコロ(0〜2)で、同点は守備側の勝ち。援軍は戦闘後に元の領地へ戻る。
  - 不可侵条約はお互い守れば両国に平和配当(兵+1、2条約まで)、片方だけ攻めれば奇襲(+2)、両方攻めれば共倒れ(次の増援−2)。破った条約は公開され、同じ相手とは2ラウンド結び直せない。
  - ★の4割で即勝利(同じラウンドに複数の国が届いたら ★の数→領地の数→兵の数 で比べる)。全ラウンド終了時は 点数(★+秘密の目標)→★の数→領地の数→兵の数 の順で比べ、最後まで同じなら同率で勝ち。領地をすべて失った国は、トップの国の手薄な場所で反乱軍として再起(兵4+ラウンド数の半分、隣の領地も1つ取り、そのラウンドは攻撃を受けない)。
  - 人間どうしは1対1の「密談」チャットを使える。

### 全ゲーム共通の設定

- **時間の長さ**(短め ×0.7 / ふつう / 長め ×1.5):回答・入力・相談などの制限時間をまとめて短く・長くする。各ゲームの秒数の設定(「描く時間」など)があるときは、その秒数に倍率がかかる。結果の表示や「覚える時間」のような、見せるための時間は変わらない。仕組みは `games/pace.js`(設定欄は `games/index.js` が全ゲームに自動で足す)。

## ローカルで動かす

```bash
npm install
npm run dev     # 1人でも開始できるテストモード(http://localhost:3000)
npm start       # 本番と同じ設定
```

複数人の動作確認は、別のブラウザやシークレットウィンドウで同じ招待リンクを開くと手軽です。

## Render に公開する

1. このフォルダを GitHub のリポジトリに push します。
2. Render のダッシュボードで **New → Web Service** を選び、リポジトリを指定して次のように設定します。
   - Runtime: Node / Build Command: `npm install` / Start Command: `npm start` / Instance Type: Free
   - Health Check Path(Advanced): `/healthz`
   - 環境変数は不要です(`DEV_MIN_PLAYERS` はローカルの1人テスト用なので設定しないでください)
3. デプロイが終わると `https://〜.onrender.com` のURLで遊べます。以降は GitHub に push するたびに自動で再デプロイされます。

### 無料プランの注意点

- 15分ほどアクセスがないとサーバーが眠り、次に開いたときの起動に1分ほどかかります。二次会の前に一度開いておくと安心です。
- 部屋やチャットはサーバーのメモリにだけ保存しているので、再デプロイやスリープで消えます(プレイ中に push しないこと)。

### 通信のしくみ(軽量化)

- ゲームの状態は、前回その人に送ったものとの**差分**(変わった項目だけ、`game:patch`)を送る。新しいゲームの開始・再接続のときだけ全体(`game:view`)を送り、何も変わっていなければ送らない。
- 同じ処理の中で `ctx.update()` が何度呼ばれても、送信は1回にまとめる(イベントや操作の応答より状態が後に届くことはない)。
- ゲーム一覧は入室時に1回だけ送る(`room:catalog`)。チャンネル一覧も変わったときだけ送る。
- 1KB を超える送信だけ WebSocket の圧縮をかける。

### 早押しの判定

- 画面は入室時と15秒ごとにサーバーと時計を合わせる(往復時間が一番短かった回を信じる)。ゲーム画面では `api.now()` がサーバーの時計での現在時刻。
- サーバーは10秒ごとに各接続の往復時間を自分で測る(`ctx.rtt(playerId)`。画面の自己申告は使わない)。
- 押した画面は「サーバーの時計で何時に押したか」(イベントの timeStamp まで戻した値)を送り、サーバーはそれを往復時間からありえる範囲に丸めて使う。最初の押しが届いてから、ほかの人の押しが届きうる時間(最大0.45秒)だけ待ってから決めるので、**届いた順ではなく押した順**になる。
- 新しい表示(名付けカードでめくったカードなど)は「少し先の時刻に出す」と予約して送り、全員の画面で同時に出す。反射型(表示から押すまでの反応時間で比べる)の道具 `judgeReaction` / `NijiBuzz.Shower` も残してある。
- 申告はブラウザの開発者ツールでごまかせなくはないので、身内で遊ぶ前提の作りです。

### 共通の部品

カードを使う早押し系のゲームを作るときに使える部品です(どのゲームからも使える)。

- **カードの絵柄** `public/games/cards.js`
  - ふつうの絵(一般名詞の絵文字、82種類。`NOUN_ROWS` に行を足せば増える)と、なぞの絵(正体不明の生き物、40種類)。
  - なぞの絵は番号から SVG を自動生成するので、画像ファイルは不要で全員の画面で同じ絵になる。2体ずつ「そっくりさん」で、目の数・口・模様・色などどこか1か所だけ違う。数は `MYSTERY_COUNT` で変えられる。
  - 画面では `NijiCards.render(id)` で絵の HTML を出せる(`font-size` で大きさが変わる)。
- **山札づくり** `NijiCards.buildDeck({ size, pool, minCopies, maxCopies, mysteryShare, rng })`
  - 合計枚数は人数から決める(`autoDeckSize`:2人34枚・4人48枚・6人62枚…、30〜80枚)。ロビーの設定で変えられる。
  - 使う絵柄の種類も人数から決め、少しランダムにぶらす(`autoKinds`。ロビーで少なめ/多めにできる)。
  - 各絵柄の枚数は 2枚〜上限でランダム。上限は山札の大きさで変わる(30枚→4、50枚→6、80枚→10)。何種類使うかもランダムで、選ばれない絵柄があってよい。
  - ゲームの定義の `settings` に `...Cards.SETTINGS` を足すと「山札の枚数」「絵柄(まぜる/ふつうだけ/なぞだけ)」の設定欄が出て、`Cards.deckFromSettings(settings, 人数)` でそのまま山札を作れる。
  - `rng` に `Cards.mulberry32(種)` を渡すと毎回同じ山札になる(テスト用)。
- **早押しの判定** サーバー `games/buzz.js` / 画面 `public/games/buzz-client.js`
  - クイズ型(1人だけが答える):サーバーで `new FirstPress({ rtt, onDecide })`、`press(id, 申告時刻, { others })`。押した時刻の順で1人に決まる。
  - 反射型(全員が押して速さを比べる):サーバーで `judgeReaction({ claimedRt, claimedPressAt, showAt, rtt })`。画面では `new NijiBuzz.Shower(api, draw)` で予約時刻ちょうどに表示し、`reaction(ev)` で反応時間を出す。
  - 画面の `NijiBuzz.bindPress(root, セレクター, fn)` でタップとスペースキーをまとめて受けられる。
  - 使うゲームの定義に `client: ['cards.js', 'buzz-client.js', '<ゲーム>.js']` のように書く。サーバー側は `require('../public/games/cards.js')` と `require('./buzz')`。

### ゲームを追加するには

1. `games/` にルールのファイルを作り、`create(ctx, settings, playerIds)` で次のメソッドを持つオブジェクトを返します。
   - `action(playerId, type, payload, { isHost })` プレイヤーの操作
   - `view(playerId)` そのプレイヤーに見せる情報(手札など非公開情報はここで出し分ける)
   - `onJoin(id)` / `onLeave(id)` / `onConnectionChange()` / `dispose()`
   - 状態が変わったら `ctx.update()`、チャットへのお知らせは `ctx.system(text)`、終わったら `ctx.finish()`
   - 特定の人にだけ届けるメッセージは `ctx.post(msg, readers)`、CPUの発言は `ctx.say(id, name, text)`
   - 状態とは別に届けたい演出やログは `ctx.emitTo(playerId, type, data)`(画面側の `onEvent(type, data)` に届く)。再接続時に送り直すものは `backlog(playerId)` で返す
   - 全体チャットの発言をゲームで使うなら `onPublicChat(playerId, text)`
   - 早押しなど時間の判定には `ctx.rtt(playerId)`(往復時間)と `games/buzz.js`、画面側では `api.now()`(サーバーの時計)を使う。ホストは `ctx.hostId()`
   - チーム用チャンネルを作るなら `chatChannels(playerId)` / `chatChannel(playerId, channel)` / `onChat(playerId, channel, text)` を実装する(怪盗と探偵が例)
2. `games/index.js` の `catalog` に登録します(`settings` を書くとロビーに設定欄が自動で出ます)。
3. `public/games/<ゲームID>.js` に画面を作り、`window.GameClients[ゲームID] = { create(root, api) }` で登録します。画面ファイルは遊ぶときに自動で読み込まれるので、`index.html` を触る必要はありません(複数ファイルが要るときは、`games/` の定義に `client: ['a.js', 'b.js']` を書く)。
